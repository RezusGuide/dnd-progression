## Ответы на вопросы этапа 9

2. **«Заявлено»:** игрокам видно, это анонс. Добавь статус `DRAFT` («Черновик»): его игроки не видят вовсе, новое дело создаётся в нём. Тест на H2.
3. **axios:** да, обнови отдельным коммитом до актуальной версии без уязвимостей, затем `npm audit`. Высокие уязвимости в рантайм-зависимостях исправить, если исправление не ломает сборку. Остаток (dev-зависимости, исправления с breaking change) перечислить в отчёте.

## Часть А. Пульт ГМ

Сейчас панель ГМ = `Admin.jsx` и разделы в `pages/admin/`. Собрать в единый **пульт** с боковой навигацией: маршруты `/gm/...`, старый `/admin` редиректит на `/gm`, `/admin?setup=1` продолжает работать.

1. **«Входящие»** (`/gm`, по умолчанию):
   - одна лента всего, что ждёт решения: заявки на создание и повышение, исследовательские записки;
   - фильтр по типу, сортировка по дате;
   - «Одобрить» и «Отклонить» прямо в ленте (с комментарием), подробности раскрываются по клику;
   - сверху сводка: «Ждут решения: N · Открытых снов: N · Запечатанных посылок: N · Ближайшая сессия: …».
2. **«Сотрудники»** (`/gm/characters`): таблица **всех** персонажей.
   - Колонки: имя, игрок, класс и раса, уровень и потолок руны, статус дела, кампания, хиты, опыт, текущий сон и стадия, число аспектов.
   - Фильтры по кампании и статусу. Строка ведёт на лист.
   - **Групповые действия** над выбранными: «Начислить опыт» (число и комментарий; сервер добавляет к `experiencePoints`), «Вдохновение» (вкл/выкл), «Отправить посылку» (открывает форму Сундучка с подставленными получателями).
3. **«Выдачи»:** аспекты и предметы (то, что есть сейчас), плюс опыт.
4. **«Пропуска»:** аккаунты (как сейчас).
   - **Убрать UI «Расширенные роли»** и неиспользуемый код кастомных ролей и секций на фронтенде.
   - На бэкенде упростить до двух ролей: `OWNER` = ГМ, `MEMBER` = сотрудник. Строки ролей в базе не удалять.
   - Если механизм секций нигде не нужен, удалить его из кода (`SectionGate` уже удалён) и проверить тестами, что права не изменились: гость читает публичное, сотрудник правит своё, ГМ всё.
5. **«Справочник», «Архив», «Сны», «Сундучок»:** существующие разделы, переехавшие в пульт.
6. **«Календарь»:** подборы и сессии с точки зрения ГМ (ссылки на существующие экраны).
7. **«Шпаргалка»:**
   - **статическая часть** из правил 5e (SRD 5.1): модификаторы, мастерство, СЛ, деньги, путешествия, отдых, укрытия, падение, удушье, концентрация, пороги опыта, опыт монстров по CR;
   - **калькулятор сложности боя:** выбрать персонажей (или кампанию), добавить монстров по CR и количеству, получить «Лёгкий / Средний / Сложный / Смертельный» по правилам DMG 2014: пороги на персонажа и множитель числа монстров с поправкой на размер группы меньше 3 и от 6. Функции в `dnd-rules` с тестами;
   - **блок «Мои правила мира»:** Markdown-заметка ГМ, хранится в базе (таблица `gm_note`, одна запись), видна только ГМ. **В репозиторий ничего из правил мира не писать**, Batyr перенесёт их сам.
8. **«Журнал»:** `GmActionLog` (кто, что, над кем, когда, краткое описание). Пишется при одобрениях и отказах, выдачах, посылках, смене статусов статей и снов, начислении опыта, смене стадий. Список с фильтром и пагинацией.

**Тесты:**
- начисление опыта группе;
- права (не-ГМ получает 403 на всех `/api/admin/**`);
- журнал пишется на одобрение записки;
- калькулятор боя (пара эталонных случаев из DMG).

**Тексты:** раздел «Пульт ГМ» в `copy.md`. Пункт навбара «Панель ГМ» переименовать в «Пульт ГМ» везде (`copy.md`, ROADMAP не трогай).

## Часть Б. Подготовка к выпуску

1. **Продовая конфигурация:**
   - при профиле `prod` (Railway выставляет `SPRING_PROFILES_ACTIVE=prod`) приложение **не стартует**, если `JWT_SECRET` не задан или равен dev-значению по умолчанию, или если `CORS_ALLOWED_ORIGINS` пуст или содержит `localhost`. Понятная ошибка в лог. Тест;
   - `ddl-auto=update` оставить. Перечисли все новые таблицы и колонки ветки `zlatopryady` против `main`, отдельно отметь колонки с `NOT NULL` без значения по умолчанию: они упадут на существующих строках.
2. **Docker:** собрать образ бэкенда локально (`docker build`), если Docker доступен. Если нет, проверь `./gradlew bootJar` и опиши. Убедиться, что `resources/data` и `resources/seed` попадают в jar.
3. **Фронтенд:**
   - `npm run build` и предпросмотр `vite preview` со сборкой: проверь, что маршруты открываются при прямом заходе (`vercel.json`);
   - `VITE_API_URL` описан в `.env.example`.
4. **`docs/zlatopryady/RELEASE.md`:** чек-лист выпуска для Batyr по шагам:
   1. **Бэкап Neon:** создать ветку базы (branch) в дашборде Neon перед выпуском, как откатиться.
   2. **Переменные Railway:** полный список, какие новые.
   3. **Мерж:** мерж `zlatopryady` → `main` (Batyr делает сам), пуш, деплой Railway, проверка логов (сидирование справочников, статей, миграция сумок, `NOT NULL`-фикс `accuracy_percentage`).
   4. **Деплой Vercel**, проверка `VITE_API_URL`.
   5. **Первичная настройка:** если ГМ уже есть в базе, `/admin?setup=1` не нужен.
   6. **Смоук-тест после выпуска** (10–15 пунктов: вход, Приёмная, лист старого персонажа, мастер, исследование, Сундучок, календарь, Мир, Сны, пульт ГМ).
   7. **SQL чистки осиротевших таблиц:** отдельным файлом `docs/zlatopryady/cleanup-orphans.sql` с `DROP TABLE IF EXISTS` для всех таблиц удалённых разделов и старой магии, **закомментированным по умолчанию**, с предупреждением «только после бэкапа». В списке обязательно `people` и `connections` (личные данные).
   8. **Если что-то пошло не так:** откат Railway и Vercel на предыдущий деплой, переключение на ветку бэкапа Neon.
5. **README:** актуализировать (разделы сайта, стек, запуск, ссылка на RELEASE.md).
6. **Финальная регрессия:** полный прогон тестов. Ручной проход по всем разделам на подставном API или на H2-бэкенде с временным сидером (не коммитить), сводная таблица «раздел → работает / замечания».
