## Цель

Игроки живут в разных часовых поясах (например, Канада, Россия, Казахстан). Каждый один раз отмечает своё свободное время **в своём местном времени** и окно сна. ГМ создаёт подбор, и сайт находит окна, когда свободны все (или нужный минимум) и никто не спит. Каждый видит окна в своём времени. ГМ назначает сессию, она появляется в Приёмной с обратным отсчётом и выгружается в календарь (`.ics`).

## 1. Модель (бэкенд)

Всё привязано к **пользователю**, а не к персонажу.

- **`AvailabilityProfile`:**
  - `user`, `timezone` (IANA, например `America/Toronto`);
  - `sleepStart`, `sleepEnd` (местное время, по умолчанию 00:00–08:00; окно может переходить через полночь);
  - `weeklyGrid`: строка из 336 символов `0`/`1`, 7 дней × 48 получасов, начиная с понедельника 00:00 местного времени;
  - `updatedAt`.
- **`AvailabilityException`:** `user`, `date` (местная дата), `kind` (`BUSY` / `FREE`), `startMinute`, `endMinute` (или весь день).
- **`SessionPoll`:**
  - `id`, `title`, `campaign` (nullable), `participants` (пользователи);
  - `dateFrom`, `dateTo` (даты в поясе ГМ), `gmTimezone`;
  - `durationMinutes` (кратно 30), `minParticipants` (по умолчанию все);
  - `status` (`OPEN` / `SCHEDULED` / `CANCELLED`), `createdBy`, `createdAt`.
- **`GameSession`:** `poll` (nullable), `title`, `startUtc`, `durationMinutes`, `campaign`, `createdBy`, `note`.

## 2. Ядро расчёта

Чистый класс `AvailabilityCalculator` без Spring, с юнит-тестами.

1. **Свободные получасы участника в UTC.** Для каждой местной даты диапазона (с запасом ±1 день) для каждого получаса, где в `weeklyGrid` стоит `1`:
   - местное время превращается в момент UTC через `ZonedDateTime.ofLocal`;
   - если местного времени не существует (переход на летнее время), получас пропускается;
   - если время существует дважды, берутся оба момента.
2. Затем вычесть окно сна (местное), применить исключения (`BUSY` вычитает, `FREE` добавляет, но **не** внутри сна) и оставить только моменты внутри диапазона подбора.
3. **Кандидаты:** каждый старт с шагом 30 минут, где весь интервал длительности свободен у не меньше чем `minParticipants` участников. Участники без профиля считаются недоступными и помечаются.
4. **Оценка кандидата:**
   - `+100` за каждого доступного участника;
   - `−5` за каждый «неудобный» получас у каждого участника (местное время до 09:00 или после 23:00);
   - `−1` за каждый день от начала диапазона.
5. **Результат:** до 10 лучших **непересекающихся** окон (жадно: берём лучшее, выкидываем пересекающиеся, повторяем). Для каждого окна: старт и конец в UTC, кто доступен, кто нет, местное время каждого участника.

**Тесты (обязательно):**
- Торонто + Москва + Алматы: при реалистичных сетках окно находится и ни у кого не попадает на сон. Проверить конкретное ожидаемое окно.
- **Переход на зимнее время в Торонто** (1 ноября 2026): сетка «пятница–воскресенье 18:00–22:00» даёт правильные моменты UTC до и после перехода.
- Окно сна через полночь (23:00–07:00).
- `BUSY` убирает окно, `FREE` не пробивает сон.
- `minParticipants` меньше общего числа.
- **Алматы в октябре 2026 = UTC+5** (Казахстан перешёл на единый пояс в 2024). Если тест падает, значит в JDK устаревшие данные часовых поясов. Напиши об этом в отчёте и проверь образ в `Dockerfile` (нужен свежий `tzdata` или JDK с актуальной базой).

## 3. API

- **Своё время:** `GET`/`PUT /api/me/availability` (профиль и сетка), CRUD `/api/me/availability/exceptions`.
- **Подборы:**
  - `GET /api/polls`: свои, где участник; ГМ видит все;
  - `GET /api/polls/{id}`: подбор, окна (считаются на лету), список «не заполнил расписание», а также **тепловая карта**: для каждого получаса диапазона число доступных;
  - `POST /api/polls`: только ГМ;
  - `POST /api/polls/{id}/schedule` с телом `{startUtc}`: только ГМ; создаёт `GameSession`, переводит подбор в `SCHEDULED`, публикует объявление;
  - `POST /api/polls/{id}/cancel`.
- **Сессии:** `GET /api/sessions?upcoming=true`, `GET /api/sessions/{id}/ics` (VEVENT, `DTSTART` в UTC с `Z`, `UID`, `SUMMARY`, `DESCRIPTION` со ссылкой на сайт).
- **Объявление при назначении:** заголовок «Сессия назначена: {название}», в тексте время в поясе ГМ и строка «В Приёмной время показано по вашему поясу.»
- **Приватность:** другим участникам видны только имя и часовой пояс пользователя (например, «Аня · Торонто»), сетка остальных не отдаётся. ГМ видит всё.
- **Тесты на H2:** только ГМ создаёт и назначает; участник видит свой подбор; не-участник не видит; `.ics` корректен.

## 4. Фронтенд

Пункт навбара «Календарь». Страница `/calendar`, три вкладки.

1. **«Моё время»:**
   - часовой пояс: выпадающий список с поиском, по умолчанию `Intl.DateTimeFormat().resolvedOptions().timeZone`, кнопка «Определить автоматически»;
   - окно сна: два поля времени;
   - **недельная сетка** 7×48: зажать мышь и провести, чтобы закрасить или стереть. Строки — дни (пн–вс), столбцы — получасы, подписи каждого часа. Сон закрашен штриховкой и не редактируется. Быстрые кнопки: «Будни вечером 19–23», «Выходные днём 12–20», «Очистить»;
   - **исключения:** месячный календарь, клик по дате открывает «Занят весь день / Занят с… по… / Свободен с… по…»;
   - кнопка «Подшить расписание», статус «Подшито».
2. **«Подбор сессии»:**
   - список подборов; у ГМ кнопка «Новый подбор»: название, кампания (подставляет участников) или ручной выбор, даты, длительность, минимум участников;
   - **страница подбора:**
     - **тепловая карта** в поясе зрителя (строки — даты, столбцы — часы, цвет — сколько свободно, при наведении кто именно);
     - **список лучших окон.** Строка: «Пт, 30 октября, 19:00–22:00 (ваше время)», под ней местное время каждого («Аня · Торонто 10:00–13:00», «Батыр · Алматы 20:00–23:00»), значок «неудобно» у тех, кому рано или поздно;
     - кто не заполнил расписание;
     - у ГМ кнопка «Назначить» на каждом окне, с подтверждением.
3. **«Сессии»:** ближайшие и прошедшие, время в поясе зрителя, обратный отсчёт до ближайшей, кнопка «В календарь (.ics)».

**Приёмная:**
- блок «Ближайшая сессия» с местным временем и отсчётом;
- если у пользователя нет профиля: `Hint` с котом «Отметьте своё свободное время, чтобы ГМ мог подобрать сессию.» и ссылка.

**Все даты и время** через `Intl.DateTimeFormat('ru-RU', { timeZone })`. Пояс зрителя берётся из его профиля, а если профиля нет, из браузера.
