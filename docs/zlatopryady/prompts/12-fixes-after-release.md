# Промпт 12: исправления после выпуска

Сайт выпущен: `zlatopryady` смержена в `main` **на ПК**, и `main` на GitHub ушёл вперёд. **Сначала `git checkout main` и `git pull`**, работать в `main` (или в ветке от него), коммитить, **не пушить** без разрешения Batyr. Бэкенд против Neon не запускать: боевой бэкенд работает на ПК.

## 1. Скрипты домашнего хостинга

Найдено при выпуске.
1. **`stop.ps1`** останавливает только один `run.ps1`. Если их было два (окно и задача Планировщика), второй принимает остановку за падение и перезапускает сервер. Исправить: останавливать **все** процессы `run.ps1` и все `java` с `backend.jar` (по командной строке, `Get-CimInstance Win32_Process`), затем проверить, что ничего не осталось.
2. **`run.ps1`:** при старте проверять, не запущен ли уже другой экземпляр (именованный mutex, например `Global\ZlatopryadyBackend`) и не занят ли порт 8080. Если да, выйти с понятным сообщением, без цикла перезапусков.
3. **Заглушки:** `check-env.ps1` и `ProdConfigCheck` должны выдавать ошибку, если любое значение в `.env.home` (а на бэкенде `CORS_ALLOWED_ORIGINS` и `SITE_URL`) содержит `<` или `>`. Текст: «В настройках осталась заглушка из шаблона: {ИМЯ}». Тест на `ProdConfigCheck`.

## 2. Ночная тема на всю ширину

На страницах «Стол исследований» и «Соединение аспектов» тёмный фон занимает только блок контента, справа остаётся светлая полоса, особенно при уменьшенном масштабе браузера. Ночная тема должна закрашивать **всё окно** (фон `body` или обёртки страницы на всю ширину и высоту, `min-height: 100vh`), пока открыта страница. При уходе со страницы вернуть дневную. Проверить при масштабе 67%, 100%, 150% и на «Снах».

## 3. Стол исследований: сделать правило очевидным

Batyr (автор правил) собрал цепочку из базовых аспектов и не понял, почему всё красное. Значит, игроки тоже не поймут.

1. **Причина красного.**
   - Между соседними занятыми клетками, которые **не связаны**, рисовать короткую красную пунктирную черту поверх стыка гексов.
   - При наведении на такую черту подсказка: «Рассвет и Туман не связаны. Туман = Пар + Тень.»
   - Для одинаковых соседей: «Одинаковые аспекты не связаны.»
2. **Правило рядом со статусом,** постоянно, мелким текстом: «Связаны только аспект и его составляющие: Туман связан с Паром и Тенью. Базовые аспекты между собой не связаны.»
3. **«Родословная» якорей.**
   - Кнопка «Подсказка: родство якорей» показывает кратчайшую цепочку **по справочнику** между каждой парой якорей, только названиями, без клеток. Например: «Туман → Тень → Кошмар → Сон».
   - Плюс подсказка про длину: «Якоря стоят в {d} клетках друг от друга. Удлиняйте цепочку ходами туда-обратно (Тень → Туман → Тень) или обходом по дуге.»
   - Вычисляется на фронтенде по `aspects.json` (BFS). Тест.
   - **Чётность:** граф связей почти двудольный, поэтому цепочка ровно на `d−1` клеток (по прямой) часто невозможна. Batyr на этом застрял: Туман → … → Мираж → Сон → якорь-Сон, где последний Сон не связан с якорем.
     - Подсказка должна показывать **готовую последовательность названий нужной длины**: сначала проверить длины `d−1`, `d`, `d+1` (BFS по состоянию «аспект, длина»). Например: «6 клеток: Тень → Туман → Тень → Туман → Тень → Кошмар (обходите по дуге, по прямой здесь 5 клеток)».
     - Тест на теме «Безмолвный образ».
   - Красный стык между последним аспектом и якорем того же типа подписывать отдельно: «Рядом с якорем стоит такой же аспект: он не связан с якорем. Поставьте сюда родственный якорю аспект.»
4. **Подсветка при выборе аспекта в сумке:** соседние **пустые** клетки, куда этот аспект можно поставить, чтобы он связался с уже стоящим соседом, слегка подсвечиваются.
5. **Подсказка кота** при первом визите: заменить текст на правило из пункта 2 и пример.
6. **Подсветка связанных при наведении** сейчас выглядит как сбой: аспекты загораются без объяснения.
   - Пока курсор на аспекте, над сумкой показывать строку «Тлен связан с: Тень, Разлом, Жизнь».
   - Подсветку связанных сделать отличимой от выбранного аспекта: выбранный — плотная рамка рассвета, связанные — пунктирная латунная рамка и значок цепочки.
7. **Кнопка «Подать записку» неактивна без объяснения.** Рядом с неактивной кнопкой (и в `title`) писать причину: «Сначала соедините все якоря» / «Уберите висящие аспекты: N» / «Не хватает аспектов в сумке».
8. **Проверь, что постановка аспекта на клетку работает** на боевой сборке: клик по аспекту в сумке, затем по пустой клетке; повторный клик по клетке снимает. Batyr пишет «исследование не происходит». Если это просто неактивная кнопка, пунктов 6–7 достаточно. Если клетки не ставятся, найди и почини.

## 3а. Баг подсчёта в сумке после отправки

- **Наблюдение:**
  - до отправки записки «Туман: осталось 97 из 99» (2 на сетке);
  - после отправки «осталось 95 из 97».
- **Причина:** сервер списал верно (99 → 97), но сетка записки на рассмотрении всё ещё вычитается из сумки второй раз.
- **Исправить:** для темы с открытой (`PENDING`) или одобренной запиской положенные на сетку аспекты не вычитать из «осталось». Показывать «97 из 97».
- Тест на фронтенде.
