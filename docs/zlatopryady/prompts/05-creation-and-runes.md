## Правила кампании для этого этапа

Они записаны в ROADMAP, раздел 2.

- **Руна.** У каждого персонажа есть уровень руны:
  - обычная = потолок **10** уровня;
  - аристократическая = **15**;
  - королевская = **20**.
- **Допуск** — это одобренная ГМом заявка. Она разрешает уровень выше потолка руны. В мире допуски выдаёт Секретарша Санни, на сайте это делает ГМ.
- **Новый персонаж** создаётся со статусом «На рассмотрении». Игрок видит и правит его лист, но в кампанию он попадает после одобрения ГМом. Руна выше обычной требует отдельной отметки ГМа при одобрении.
- **Уровень повышает только ГМ.** Игрок подаёт заявку на повышение из листа. Если новый уровень выше потолка, заявка помечается «Сверх потолка руны: нужен допуск».
- **Заклинания при создании.** Заклинатель выбирает только **заговоры** (число по таблице класса, 1 уровень SRD). Заклинания 1 круга и выше появляются через исследования (этап 6) или выдаются ГМом.
- **Уже существующие персонажи** после миграции получают обычную руну и статус «Одобрен». Переподтверждать их не нужно.

## 1. Справочники (JSON, единый источник)

`backend/src/main/resources/data/`. Отдаются публичным `GET /api/data/{name}` (только имена из белого списка). Фронтенд берёт их через API, своих копий не держит.

- **`races.json`:** 9 рас SRD 5.1, по одной подрасе там, где они есть в SRD: холмовой дварф, высший эльф, легконогий полурослик, скальный гном.
  - Поля: ключ (как в базе: `Human`, `Elf`…), `nameRu`, бонусы характеристик, скорость, размер, языки, короткий список черт на русском (одна строка на черту, своими словами, не копируя текст книг).
  - Плюс вариант **«Другое»**: игрок вводит название и сам расставляет бонусы, например +2/+1.
- **`classes.json`:** 12 классов.
  - Кость хитов, спасброски, число и список навыков на выбор, владения (кратко);
  - базовая характеристика заклинаний (или `null`);
  - число заговоров на 1 уровне;
  - два варианта стартового снаряжения строками на русском (по SRD).
- **`backgrounds.json`:**
  - «Прислужник» (единственная предыстория в SRD 5.1);
  - четыре **своих** предыстории мира (черновик, ГМ поправит):
    - «Клерк конторы»: Анализ, Убеждение;
    - «Механик-паровик»: Атлетика, Ловкость рук;
    - «Посыльный Тенгена»: Скрытность, Выживание;
    - «Аптекарь»: Медицина, Природа;
  - вариант «Своя»: название, два навыка, владения и языки текстом.
  - У каждой одна строка описания в канцелярском тоне.
- **`runes.json`:** три уровня руны (ключ, название, потолок, описание одной строкой).

## 2. Бэкенд

- **`Character`:**
  - `runeTier` (`COMMON` / `ARISTOCRAT` / `ROYAL`, по умолчанию `COMMON`);
  - `approvalStatus` (`PENDING` / `APPROVED` / `REJECTED`, по умолчанию `APPROVED` для существующих строк: проверь, как `ddl-auto=update` заполнит колонку, при необходимости сделай заполнение в `DataSeeder` одноразово и идемпотентно);
  - `clearanceLevel` (Integer, null): максимальный уровень, разрешённый допуском;
  - `hitDiceUsed`.
- **`AdmissionRequest`:**
  - `id`, `character`, `type` (`CREATION` / `LEVEL_UP`), `requestedLevel`, `requestedRuneTier` (для `CREATION`), `aboveCap` (boolean);
  - `status` (`PENDING` / `APPROVED` / `REJECTED`), `playerComment`, `gmComment`, `createdAt`, `decidedAt`, `decidedBy`.
- **Создание персонажа** `POST /api/characters` принимает полный набор из мастера и создаёт персонажа `PENDING` вместе с заявкой `CREATION`.
  - Сервер проверяет:
    - сумма характеристик не нарушает выбранный метод (для «стандартного набора» и «покупки очков»);
    - навыки взяты из разрешённых списков;
    - заговоры есть в списке класса и их число не больше лимита;
    - стартовый уровень не выше потолка руны.
  - Ошибки возвращаются на русском.
- **Защита полей.** Игрок через `PUT` персонажа **не может** менять `level`, `runeTier`, `approvalStatus`, `clearanceLevel`: сервер игнорирует эти поля, если пишет не ГМ. ГМ может менять всё.
- **Заявки:**
  - `POST /api/characters/{id}/level-up-request`: игрок, владелец, только `APPROVED`-персонаж и только если нет открытой заявки;
  - `GET /api/admin/requests?status=PENDING`;
  - `POST /api/admin/requests/{id}/approve|reject` с `gmComment`.
  - Одобрение `LEVEL_UP`: `level = requestedLevel`; если `aboveCap`, то и `clearanceLevel = requestedLevel`.
  - Одобрение `CREATION`: `approvalStatus = APPROVED`, руна по заявке.
- **Тесты на H2:**
  - игрок не может поднять себе уровень через `PUT`;
  - заявка сверх потолка помечается `aboveCap`;
  - одобрение выставляет уровень и допуск;
  - создание с лишним заговором отклоняется.

## 3. Мастер «Заведение личного дела»

Маршрут `/characters/new`. Кнопки «Завести личное дело» и `?new=1` ведут сюда. Старую форму создания удалить.

**Слева** вертикальная лента шагов (на узком экране сверху). **Справа** шаг. **Внизу** «← Назад» и «Далее →». **Сбоку** «Сводка дела»: что уже выбрано, и итоговые характеристики с бонусами расы.

Черновик хранится в `localStorage`, чтобы обновление страницы не теряло ввод. Обернуть в try/catch.

1. **Раса:** карточки рас (`Dossier`) с бонусами и чертами. «Другое» с ручными бонусами.
2. **Класс:** карточки классов, кость хитов, базовая характеристика, «заклинатель» или нет. Подсказка кота: «Не знаете, кого выбрать? Воин прост в освоении, волшебник — для любителей читать.»
3. **Предыстория:** карточки и «Своя».
4. **Характеристики.** Три метода вкладками:
   - **Стандартный набор:** раздать 15, 14, 13, 12, 10, 8 через выпадающие списки, каждое значение один раз;
   - **Покупка очков:** 27 очков, значения 8–15, таблица стоимости SRD, счётчик остатка;
   - **Броски:** кнопка «Бросить 4к6» на каждую характеристику (отбросить меньший кубик). Результат и кубики видны. Перебросить нельзя без кнопки «Сбросить все броски».
   - Ниже итог с бонусами расы и модификаторы. Правила в `dnd-rules.js` с тестами.
5. **Навыки и владения:** навыки от предыстории отмечены и заблокированы; навыки класса выбираются до лимита.
6. **Заговоры** (только для заклинателей, иначе шаг пропускается): список заговоров класса из `spells.json` с описанием по клику, выбор до лимита.
7. **Снаряжение:** вариант А или Б из класса (радиокнопки), плюс поле «Дополнительно». Всё сохраняется в поле снаряжения текстом.
8. **Имя и портрет:** имя (обязательно), имя игрока, мировоззрение, портрет (как в листе), предыстория текстом (необязательно).
9. **Заявка на допуск:**
   - выбор руны (обычная по умолчанию; выше обычной с пометкой «Подтверждает ГМ»);
   - стартовый уровень (по умолчанию 1, не выше потолка руны);
   - комментарий для ГМа;
   - сводка всего дела.
   - Кнопка «Подать заявку». После отправки штамп «НА РАССМОТРЕНИИ» и переход в лист.

**Хиты на старте:** максимум кости хитов + мод. ТЕЛ на 1 уровне. На каждом следующем стартовом уровне среднее значение кости (округление вверх) + мод. ТЕЛ. В `dnd-rules` с тестами.

## 4. Лист, Приёмная, панель ГМ

- **Шапка листа:**
  - руна значком (шестерёнка с руной ᛉ, цвет по уровню), подпись «Руна: обычная · потолок 10»;
  - статус дела штампом (`pending` / `approved` / `rejected` с комментарием ГМа);
  - кнопка «Заявка на повышение», когда хватает опыта (вместо текущей плашки). Если открыта заявка, вместо кнопки «Заявка на рассмотрении».
  - В режиме правки у игрока поле уровня только для чтения, с подсказкой «Уровень повышает ГМ».
- **Приёмная:** блок «Мои заявки»: открытые и последние решения. ГМ вместо него видит «Ждут решения: N» со ссылкой на панель.
- **Панель ГМ,** раздел «Заявки»:
  - список открытых: персонаж, игрок, тип, уровень, руна, «сверх потолка», комментарий игрока, ссылка на лист;
  - кнопки «Одобрить» и «Отклонить» с полем комментария, `Stamp` при решении;
  - история решений под списком.
- **Кампании:** персонажи `PENDING` показываются с пометкой «На рассмотрении».
