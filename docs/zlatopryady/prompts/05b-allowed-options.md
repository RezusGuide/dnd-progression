## Ответы на вопросы этапа 5

## Цель

Мастер создания предлагает ровно тот набор рас и классов, который разрешил ГМ. ГМ может менять статусы и открывать закрытое из своей панели, без правки репозитория.

## 1. Статусы

| Статус | Игрок в мастере | ГМ |
|---|---|---|
| `allowed` | выбирает | видит |
| `unlockable` | видит карточку с замком и текстом «Пока закрыто. Откроется по ходу кампании.» **Условие не показывать** | видит условие (флаг и свою подпись) |
| `undecided` | не видит | видит с пометкой «Не решено» |
| `closed` | не видит | видит «Закрыто: только форма во сне». Выдача формы будет на этапе 9 |
| `npc_only` (классы) | не видит | видит «Только для НИП» |

## 2. Данные

- Слить `allowed-options.json` с `races.json` и `classes.json`: у каждой записи поля `status`, `source` (код книги), `unlock` (для `unlockable`).
- **Ключи.**
  - У рас и классов, которые уже есть в справочниках этапа 5, оставить прежние ключи (`Human`, `Half-Elf`, `Half-Orc` и т.д.): по ним хранятся существующие персонажи.
  - Новым записям ключ = поле `en` из списка (`Kenku`, `Thri-kreen`, `Artificer`…).
  - `id` из списка можно сохранить как отдельное поле, но ключом не делать.
- **Механика рас не из SRD.** Тексты платных книг копировать нельзя, поэтому у них только название, источник и:
  - бонусы по правилу гибкого происхождения: игрок выбирает +2/+1 или +1/+1/+1 в любые характеристики;
  - скорость (по умолчанию 30) и размер (Маленький или Средний), игрок может поправить;
  - черты: поле «Черты расы» на шаге расы, игрок переписывает их из книги, источник подсказкой «См. {код книги}». Текст уходит в «Умения и особенности».
  - У рас SRD 5.1 (человек, дварф, гном, полурослик, полуэльф, тифлинг, драконорождённый, эльф, полуорк) механика остаётся как сейчас, плюс переключатель «Гибкие бонусы» с тем же правилом.
- **Классы не из SRD.**
  - **Изобретатель** (`Artificer`): кость к8, спасброски ТЕЛ и ИНТ, 2 навыка из Анализа, Истории, Магии, Ловкости рук, Медицины, Природы, Восприятия; базовая характеристика ИНТ; 2 заговора; ячейки как у половинного заклинателя с округлением вверх, начиная с 1 уровня. Добавь эту таблицу в `dnd-rules` с тестом.
  - **Алхимик** и **Егерь**: механику не выдумывать. Поля `hitDie`, `saves`, `skillChoice`, `spellAbility`, `cantrips` оставить `null`. Мастер в этом случае просит игрока ввести их самому («Заполните по книге, ГМ проверит при одобрении»), а сервер такие поля не валидирует против справочника.
  - Заговоры для классов, у которых нет списка в `spells.json`: выбор из всех заговоров с пометкой «Сверьтесь с книгой».

## 3. Переопределения ГМ (без правки репозитория)

- **Таблица `option_override`:** `kind` (`RACE` / `CLASS`), `key`, `status`. Если запись есть, она важнее статуса из JSON.
- **Таблица `unlock_flag`:** `key`, `gmLabel` (подпись, видит только ГМ), `unlocked` (boolean). При старте создаются строки для всех ключей из `unlock`, если их ещё нет.
- **`GET /api/data/races` и `/api/data/classes` для всех, кроме ГМ:**
  - отдают только `allowed` и `unlockable`;
  - открытые флагом `unlockable` отдаются как `allowed`;
  - у закрытых `unlockable` нет поля `unlock` и подписи.
  - **Проверь это тестом на H2.**
- **ГМ:** `GET /api/admin/options` (полный список с переопределениями и флагами), `PUT /api/admin/options/{kind}/{key}` (статус), `PUT /api/admin/unlock-flags/{key}` (`unlocked`, `gmLabel`).
- **Сервер при создании персонажа** отклоняет расу или класс, которые для игрока не `allowed`, с текстом «Эта раса пока закрыта для оформления.» Существующих персонажей это не касается.

## 4. Панель ГМ, раздел «Справочник»

- Две таблицы, «Расы» и «Классы»: название, источник, статус (выпадающий список), для `unlockable` ещё флаг открытия.
- Фильтр по статусу. Счётчики сверху: «Доступно 27 · Откроется позже 6 · …».
- Блок «Условия открытия»: каждая строка `unlock_flag` с полем подписи и переключателем «Открыто».
