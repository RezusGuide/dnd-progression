# Промпт 11: бэкенд на домашнем ПК вместо Railway

Дополнительный этап. Ветка `zlatopryady`. **Не пушить, не мержить, не деплоить.** Бэкенд против Neon не запускать: боевой запуск делается на другом компьютере (см. ниже).

## Что изменилось

Пробный период Railway закончился. Бэкенд будет работать на настольном ПК Batyr (Windows, проводной интернет), пока ПК включён.

**Важно: ты (Code) сейчас работаешь на ноутбуке Batyr, а не на том ПК.** Значит, здесь ты только пишешь код, скрипты и инструкцию. Всё, что относится к самому серверу (проверка окружения, установка, автозапуск, боевой запуск), Batyr сделает на ПК по `HOME-HOSTING.md`. Ничего из этого не регистрируй и не настраивай на ноутбуке.

Решение принято:
- **публичный доступ:** Tailscale Funnel (бесплатно, постоянный адрес `https://<пк>.<tailnet>.ts.net`, без домена и без проброса портов: у провайдера может быть серый IP);
- **база:** остаётся в Neon;
- **фронтенд:** остаётся на Vercel.

## Цель

Batyr запускает сайт со своего ПК одной командой, а при входе в Windows бэкенд стартует сам. Сайт на Vercel ходит к ПК через Tailscale Funnel. Когда ПК выключен, сайт честно об этом говорит.

## 1. Проверка окружения (делается на ПК, не здесь)

На ноутбуке это не проверяй. Вместо этого сделай скрипт `deploy/home/check-env.ps1`, который Batyr запустит на ПК. Скрипт выводит:
- `java -version`: нужна 21;
- есть ли `tailscale` (`tailscale version`);
- свободен ли порт 8080;
- версия Windows.

Если чего-то нет, скрипт пишет точную команду установки, например `winget install EclipseAdoptium.Temurin.21.JDK` и `winget install Tailscale.Tailscale`.

## 2. Бэкенд: что добавить в код

1. **`GET /api/health`** (публичный): `{ "status": "ok", "version": "<git sha или время сборки>" }`. Без обращения к базе. Плюс `GET /api/health/db` (публичный): `ok` или `degraded`, с таймаутом 2 секунды. Тест.
2. **Ограничение попыток входа.** Сайт теперь торчит из домашнего ПК, а защиты от перебора паролей нет.
   - Не больше 5 неудачных входов на одну почту за 10 минут, затем блокировка на 10 минут. Ответ `429` с текстом «Слишком много попыток. Подождите 10 минут.»
   - Хранить в памяти (`ConcurrentHashMap` с очисткой), без новых таблиц.
   - Тест.
3. **Заголовок `X-Forwarded-*`.** Funnel проксирует запросы, поэтому включи `server.forward-headers-strategy=framework`, чтобы ссылки и редиректы строились от публичного адреса. Проверь, что CORS и `.ics` (`SITE_URL`) не ломаются.
4. **Профиль `home`** (поверх `prod`, запуск с `SPRING_PROFILES_ACTIVE=prod,home`):
   - `server.address=127.0.0.1`: бэкенд слушает только локально, наружу его выводит Funnel, а другие устройства в домашней сети до него не достучатся;
   - логи в файл `%LOCALAPPDATA%\zlatopryady\logs\backend.log` с ротацией (10 МБ × 5).

## 3. Скрипты запуска (`deploy/home/`)

PowerShell, комментарии на русском.

- **`.env.home.example`:** шаблон переменных
  - `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`;
  - `JWT_SECRET`;
  - `CORS_ALLOWED_ORIGINS` (адрес сайта на Vercel);
  - `SITE_URL`;
  - `SPRING_PROFILES_ACTIVE=prod,home`.
- **Настоящий файл:** `%LOCALAPPDATA%\zlatopryady\.env.home`, **вне репозитория**. Плюс правило в `.gitignore` на `deploy/home/.env.home` на случай, если кто-то положит его рядом.
- **`build.ps1`:** `gradlew bootJar` и копирование jar в `%LOCALAPPDATA%\zlatopryady\app\backend.jar` (чтобы пересборка в IDE не трогала работающий сервер).
- **`run.ps1`:**
  - читает `.env.home`, ставит переменные только для процесса;
  - запускает `java -XX:MaxRAMPercentage=50 -XX:+UseSerialGC -jar backend.jar`;
  - **если процесс упал, перезапускает** через 10 секунд (не больше 5 раз за 5 минут, потом пишет в лог и останавливается);
  - не показывает пароли в консоли.
- **`install-autostart.ps1`:** задача в Планировщике заданий: при входе пользователя запускать `run.ps1` скрыто, с правами пользователя (не SYSTEM). И **`uninstall-autostart.ps1`**.
- **`status.ps1`:** работает ли процесс, ответ `http://127.0.0.1:8080/api/health`, статус `tailscale funnel status`, хвост лога.
- **`funnel.ps1`:** `tailscale funnel --bg 8080` (Funnel на 443 → `localhost:8080`) и вывод публичного адреса. Плюс `funnel-off.ps1`.

**Проверь скрипты** здесь, на ноутбуке, без подключения к Neon: `run.ps1` с фиктивным `.env` на H2-профиле или с заведомо неверной базой, чтобы проверить перезапуск и логи. После проверки удали всё, что создал в `%LOCALAPPDATA%\zlatopryady`. `install-autostart.ps1` и `funnel.ps1` на ноутбуке **не запускай**.

## 4. Фронтенд: «ПК ГМа выключен»

В плашке ошибок этапа 2 различать два случая:
- `navigator.onLine === false`: старый текст «Пневмопочта не доходит. Проверьте соединение.»;
- браузер в сети, но бэкенд не отвечает (сетевая ошибка или 502/503/504 от Funnel): **«Контора закрыта. Сервер ГМа сейчас выключен, загляните позже.»** со спящим котом (вариант 503) и кнопкой «Проверить ещё раз». Кнопка дёргает `/api/health`, а не перезагружает страницу.

Приёмная гостя, если бэкенд недоступен: логотип и тот же текст вместо пустого экрана. Тесты на выбор текста.

## 5. Документация

- **`docs/zlatopryady/HOME-HOSTING.md`:** инструкция для Batyr по шагам, простым языком.
  0. **Получить код на ПК.** Ветка `zlatopryady` пока есть только на ноутбуке. Batyr сначала пушит её на GitHub (с ноутбука: `git push github zlatopryady`; это не `main`, поэтому прод на Vercel не меняется). Потом на ПК: `git clone https://github.com/RezusGuide/dnd-progression.git`, затем `git checkout zlatopryady`. После мержа в `main` уже `git checkout main` и `git pull`. На ПК нужна только Java, Node.js не нужен: фронтенд собирает Vercel.
1. **Запустить `check-env.ps1`.** Установить Java 21 и Tailscale (команды `winget`), войти в Tailscale.
  2. **Включить Funnel для своего tailnet:** в админке Tailscale включить HTTPS-сертификаты и разрешить Funnel (в настройках доступа добавить атрибут `funnel` для своего устройства). Что именно нажать, со ссылками на официальную документацию Tailscale. **Сверь текущий порядок с документацией, не по памяти.**
  3. **Заполнить `.env.home`.** Как сгенерировать `JWT_SECRET` на Windows без openssl: PowerShell-однострочник, Base64 от 48 случайных байт.
  4. `build.ps1`, затем `run.ps1`, затем `status.ps1`.
  5. `funnel.ps1`. Записать адрес.
  6. **Vercel:** `VITE_API_URL` = адрес Funnel, пересобрать. В `.env.home`: `CORS_ALLOWED_ORIGINS` = адрес Vercel, `SITE_URL` = адрес Vercel.
  7. `install-autostart.ps1`.
  8. **Электропитание Windows:** «Сон: никогда» при питании от сети. Как разрешить запуск скриптов (`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`).
  9. **Обновление сайта:** `git pull`, `build.ps1`, перезапуск (как именно).
  10. **Безопасность:**
      - наружу открыт только бэкенд через Funnel, порты на роутере не открываются;
      - домашний IP скрыт за Tailscale;
      - держать Windows обновлённой;
      - не запускать на этом ПК ничего от чужих людей.
  11. **Что будет, если ПК выключен:** сайт открывается, но показывает «Контора закрыта». Данные в Neon не страдают.
  12. **Как вернуться на облачный хостинг,** если надоест: те же переменные подходят для Render или Railway.
- **`RELEASE.md`:** раздел 2 (Railway) заменить ссылкой на `HOME-HOSTING.md`, раздел 8 (откат): для бэкенда это «остановить `run.ps1` и запустить jar предыдущей версии», сохранить предыдущий jar как `backend.prev.jar` в `build.ps1`.
- `README.md`: строка про хостинг.
