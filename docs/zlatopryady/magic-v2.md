# Магия v2: «Исследования Санни»

Спецификация этапа 6. Её ведёт планировщик. Заменяет раздел 4 ROADMAP.

Идея как в Thaumcraft 4. Заклинание открывается, если на гексагональной сетке соединить заданные аспекты-якоря цепочкой **связанных** аспектов. Готовая «исследовательская записка» уходит ГМ на одобрение.

## 3. Тема исследования и якоря

- Тема = заклинание 1 круга и выше. Заговоры не исследуются.
- **Сетка:** гексы в радиусе 4 от центра (61 клетка) для 1–5 круга, радиус 5 (91 клетка) для 6–9 круга.
- **Якоря** генерируются детерминированно. Seed = хеш `spellId`, у всех игроков и при каждой попытке результат одинаковый.
  - число якорей: 1–2 круг = 2, 3–5 = 3, 6–9 = 4;
  - аспекты якорей: разные, из набора школы, выбранные по seed;
  - минимальное расстояние между любыми двумя якорями (в гексах): 1–2 круг = 3, 3–5 = 4, 6–9 = 5. Все якоря внутри сетки.
- Генерация живёт **на бэкенде** (`ResearchTopicGenerator`), фронтенд получает готовые якоря через API.
- **Решаемость:** граф связей аспектов связный (проверить тестом). Тест также генерирует якоря для всех заклинаний из `spells.json` и проверяет, что между каждой парой якорей есть путь в графе связей, а расстояния соблюдены.

## 4. Правило верного решения

- Игрок кладёт аспекты из своей сумки в пустые клетки. Якоря занимают свои клетки заранее.
- Строим граф: вершины = все занятые клетки (якоря и положенные). Ребро между двумя **соседними** клетками есть, только если их аспекты связаны.
- **Решение верно**, если:
  1. все якоря лежат в одной компоненте связности;
  2. каждый положенный аспект принадлежит этой же компоненте (лишних «висящих» нет).
- Соседние, но не связанные клетки разрешены, они просто не дают ребра.
- Проверку делает **бэкенд** при отправке. Фронтенд делает ту же проверку для подсветки, общий алгоритм описан тестами с обеих сторон.

## 5. Сумка, соединение аспектов, стартовый набор

- Сумка = текущее поле `aspects` персонажа (`Map<String,Integer>`).
  - **Миграция:** одноразово и идемпотентно удалить ключи, которых нет в `aspects.json` (старые латинские аспекты).
- **Соединение аспектов** (замена крафта): выбрать два аспекта из сумки. Если есть рецепт, оба тратятся и получается составной. Справочник рецептов виден целиком. Разборки обратно нет.
- **Стартовый набор:** при одобрении заявки `CREATION` у заклинателя автоматически +3 каждого базового аспекта. Число задаётся в `aspects.json` (`starterKitPerPrimal`).

## 6. Исследовательская записка

- **Сущность `ResearchNote`:** `character`, `spellId`, `grid` (JSON: якоря и положенные аспекты), `spent` (JSON: аспект → количество), `status` (`PENDING` / `APPROVED` / `REJECTED`), `gmComment`, `createdAt`, `decidedAt`, `decidedBy`.
- **Отправка:**
  - сервер проверяет доступ (раздел 7), наличие аспектов и правило из раздела 4;
  - списывает положенные аспекты и создаёт записку `PENDING`;
  - открытая записка на это же заклинание блокирует новую.
- **Одобрение ГМ** добавляет заклинание в известные (`KnownSpell`), в листе ставится штамп «ОДОБРЕНО».
- **Отказ** возвращает потраченные аспекты, у игрока виден комментарий ГМ.
- **Черновик:** таблица `ResearchDraftV2` (`character`, `spellId`, `grid`), автосохранение. Старая таблица черновиков больше не используется.

## 7. Доступ к теме

- Класс заклинатель. Для классов без списка в справочнике (Алхимик, Егерь и т.п.) ограничение по списку не применяется: ГМ всё равно одобряет.
- Заклинание есть в списке класса.
- **Круг заклинания не выше максимального доступного** на текущем уровне персонажа по его таблице ячеек: полный, половинный, Изобретатель, колдун. Функция уже есть в `dnd-rules`; на бэкенде нужна такая же, с тестом на совпадение для пары уровней.
- Персонаж одобрен (`APPROVED`).
- Если тема недоступна, в каталоге показывается причина: «Не ваш список», «Нужен {N} уровень», «Дело на рассмотрении».

## 8. Экран «Стол исследований» (`/characters/:id/research`, ночная тема)

```
┌─ Каталог тем ───────┐┌──────── Сетка ────────────────┐┌─ Сумка ──────────┐
│ поиск, фильтр круга ││  якоря крупно, с рамкой        ││ значок · назв · ×3│
│ и школы             ││  положенные аспекты            ││ (связанные с       │
│ ● Волшебная стрела  ││  подсветка: зелёный контур —   ││  наведённым        │
│   1 круг · Воплощ.  ││  в общей компоненте, красный — ││  подсвечены)       │
│   статус            ││  висит отдельно                ││ [Соединить]        │
└─────────────────────┘└────────────────────────────────┘└────────────────────┘
        Статус: «Якоря соединены: 2 из 3» · [Очистить] [Подать записку]
```

- **Каталог:**
  - заклинания класса с кругом, школой и статусом: «Изучено», «На рассмотрении», «Доступно», «Недоступно: причина»;
  - описание по клику.
- **Сетка:**
  - клик по аспекту в сумке выбирает его, клик по пустой клетке кладёт, клик по положенному снимает;
  - перетаскивание по желанию;
  - у якорей замок, снять их нельзя;
  - при наведении на аспект связанные с ним аспекты подсвечиваются в сумке и на сетке. **Это главная подсказка игроку.**
  - Ребра-связи рисуются тонкими латунными линиями между связанными соседями.
- **Сумка:**
  - количество с учётом уже положенных («осталось 2 из 3»);
  - подсказка по аспекту: название, смысл, рецепт, с чем связан.
- **Подать записку:** окно подтверждения со списком, что спишется. После отправки штамп «НА РАССМОТРЕНИИ».
- **Подсказка кота** при первом визите: «Соедините якоря цепочкой. Соседи должны быть родственными аспектами, одинаковые не считаются.»
- **Узкий экран:** каталог и сумка уходят в выдвижные панели. Полировки не нужно.

## 9. Экран «Соединение аспектов» (`/characters/:id/craft`)

Два слота, сумка снизу, результат справа, справочник рецептов (таблица со значками). Кнопка «Соединить». Тексты в канцелярском тоне.

## 10. Лист и панель ГМ

- **Лист, вкладка «Магия»:**
  - кнопка «Исследования»;
  - блок «Записки на рассмотрении» (название, статус, комментарий ГМ при отказе);
  - в «Снаряжении» сумка аспектов со значками вместо старого списка.
- **Панель ГМ:**
  - раздел «Исследования»: очередь записок с превью сетки (только чтение), «Одобрить» и «Отклонить» с комментарием, история;
  - выдача аспектов (форма с новым списком и значками);
  - старые выдачи «наводок» удалить.
