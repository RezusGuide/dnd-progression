# Златопряды: дорожная карта

Этот файл главный. Если он расходится с `TZ-v1.md`, верен этот файл.
Ведёт его агент-планировщик. Code (агент, который пишет код) читает его перед каждым этапом и не меняет без просьбы.

## 0. Роли в работе

- **Batyr**: владелец проекта и ГМ кампании. Принимает решения.
- **Планировщик** (Claude в чате): пишет промпты по этапам, проверяет результат, иногда сам добавляет файлы. Всё, что он добавил или изменил, перечисляется в начале следующего промпта.
- **Code**: пишет код по промпту, проверяет сборку, коммитит в рабочую ветку, отдаёт отчёт.

## 1. Решения Batyr (21.10.2026)

1. Всё, что не связано с D&D, **удаляется полностью** (не прячется): портфолио, медиа, галерея с фото, Useful Functions, Minecraft, загрузки. Остаются только **объявления**.
2. Старую систему магии (50 аспектов Thaumcraft, крафт, сопоставление по шаблонам, `pattern` в `spells.json`) **можно выкинуть целиком** и сделать новую (раздел 4).
3. **Мобильная вёрстка пока не в приоритете.** Сайт не должен ломаться на узком экране, но отдельной полировки под телефон не делаем.
4. Стиль не «средневековый манускрипт», а **мир Санни: офисы, бюрократия, стимпанк, магия, сны**.
5. **Лист персонажа** переделываем так, чтобы игроку было понятно и удобно.
6. **Страницы ошибок 4xx и 5xx** с анимацией маскотов.
7. Новая фича: **календарь** (подбор времени сессии с учётом часовых поясов и сна). См. раздел 5.

## 2. Решения по умолчанию (Batyr может переиграть)

- **Аккаунты по-прежнему создаёт ГМ** в своей панели, открытой регистрации нет. Страница входа оформлена как «Оформление допуска».
- **Роли:** `OWNER` на экране называется «ГМ», `MEMBER` называется «Сотрудник».
- **Первичная настройка** (кто станет ГМом): `/admin?setup=1`, работает только пока ГМа нет (решено на этапе 2).
- **Тексты:** тон и словарь в `docs/zlatopryady/copy.md`. «Пропуск» значит аккаунт, «допуск» значит разрешение на уровень.
- **Язык:** только русский. Переключатель EN и английский словарь убираем на этапе 2.
- **Тесты бэкенда** гоняются на H2 (профиль `test`), а не на Neon. Бэкенд против настоящей базы Neon Code без разрешения Batyr не запускает.
- **Репозиторий публичный.** В `docs/` и коммиты не пишем ничего из секретов ГМа, даже в виде списка.
- **Данные игроков:** аккаунты, персонажи и выученные заклинания сохраняем. Запасы старых латинских аспектов при переходе на новую магию обнуляются, ГМ раздаёт новые.
- **Таблицы удалённых разделов в базе** (`people`, `connections`, `polls`, `poll_options`, `poll_votes`, `minecraft_server`, `about_profile`, `media_profile`, `media_links`, `portfolio_projects`, `download_links` и подобные) код не трогает. `ddl-auto=update` их не удалит. Batyr удаляет их вручную, когда захочет (в `people` лежат личные данные, удалить их стоит).

## 3. Что нельзя пускать на сайт и в репозиторий

- **Хранилище Obsidian в репозиторий не кладём никогда.** В нём секреты ГМа, а репозиторий на GitHub.
- В игровых разделах запрещены:
  - всё из заметки «Секреты ГМа» (конкретный список у ГМа; репозиторий публичный, поэтому здесь он не перечисляется);
  - **названия произведений, на которых основан мир и сны, и прямые отсылки к ним** (правило мета-знания). Для снов используем только внутриигровые названия дел;
  - заметки, где автор пишет о вдохновении, а также гипотезы и открытые вопросы;
  - реальные имена и контакты ГМа.
- Поэтому раздел «Мир» **не импортирует Obsidian автоматически**. Статьи для игроков лежат отдельным курируемым JSON (`world.json`), черновик готовит планировщик, утверждает ГМ.

## 4. Магия v2: «Исследования Санни»

Идея как в Thaumcraft 4: заклинание открывается, если соединить заданные аспекты цепочкой связанных аспектов на гексагональной сетке. Все справочники лежат в JSON, чтобы ГМ правил их без перекомпиляции.

### 4.1. Аспекты (`aspects.json`)

Базовые (6):
| Ключ | Название | Смысл |
|---|---|---|
| `dawn` | Рассвет | свет, огонь, жизнь |
| `shadow` | Тень | тьма, скрытность, смерть |
| `steam` | Пар | материя, механизм, движение |
| `dream` | Сон | разум, иллюзия, чары |
| `order` | Порядок | руна, защита, закон |
| `rift` | Разлом | хаос, планы, дикая магия |

Составные (черновик, ГМ правит): каждый собран из двух других.
| Ключ | Название | Рецепт |
|---|---|---|
| `gear` | Шестерня | Порядок + Пар |
| `mirage` | Мираж | Сон + Рассвет |
| `flame` | Пламя | Рассвет + Пар |
| `ward` | Оберег | Порядок + Рассвет |
| `decay` | Тлен | Тень + Разлом |
| `fog` | Туман | Пар + Тень |
| `portal` | Врата | Разлом + Порядок |
| `nightmare` | Кошмар | Сон + Тень |
| `life` | Жизнь | Рассвет + Тлен |
| `machine` | Механизм | Шестерня + Пар |
| `oracle` | Прозрение | Сон + Порядок |
| `storm` | Буря | Разлом + Пар |
| `essence` | Эссенция | Сон + Разлом *(только название, без тайны происхождения)* |

**Связь:** два аспекта связаны, если один входит в рецепт другого. Одинаковые аспекты тоже связаны.

### 4.2. Тема исследования

- Тема = заклинание из SRD 5e (`spells.json`, без полей `pattern`).
- `schools.json`: у каждой школы магии свой набор аспектов. Например, Воплощение = Рассвет, Разлом, Пламя, Буря; Ограждение = Порядок, Оберег, Шестерня.
- **Якоря:** берутся из набора школы детерминированно (хеш от `spellId`), поэтому у всех и при каждой попытке одинаковые. Их число и расстояние зависят от уровня заклинания: 1–2 уровень = 2 якоря, 3–5 = 3, 6–9 = 4. Чем выше уровень, тем дальше якоря друг от друга.
- **Заговоры** не исследуются, их выбирают при создании персонажа.

### 4.3. Стол исследований

- Сетка шестиугольников, якоря стоят заранее.
- Игрок кладёт аспекты из своей сумки в пустые клетки.
- **Решение верно,** если все якоря соединены в одну связную группу через соседние занятые клетки и каждая пара соседних занятых клеток связана (4.1). Проверяет **бэкенд**, фронтенд только подсвечивает ошибки.
- Можно сохранить черновик.
- **Отправка** списывает положенные аспекты и создаёт «Исследовательскую записку» со статусом «На рассмотрении».
- **ГМ одобряет или отклоняет** с комментарием. Одобрено: заклинание появляется в листе и ставится штамп «ОДОБРЕНО». Отклонено: аспекты возвращаются.
- **Доступ:** класс должен быть заклинателем, заклинание должно быть в его списке, а уровень заклинания должен быть доступен на текущем уровне персонажа. Логика `CasterClasses` сохраняется.

### 4.4. Откуда берутся аспекты

- ГМ выдаёт их в панели.
- Награды из Сундучка (этап 7).
- Позже: «разбор» предмета из сна. ГМ задаёт состав предмета, игрок разбирает его на аспекты.

### 4.5. Что удаляется

50 аспектов TC4, `AspectRecipe` и сидер рецептов, `AspectCraft.jsx`, старая оценка исследования по шаблонам, поле `pattern` в `spells.json`, подсказки старого формата.

## 5. Календарь «Подбор сессии»

- **Профиль каждого:**
  - часовой пояс IANA (по умолчанию из браузера, `Intl.DateTimeFormat().resolvedOptions().timeZone`);
  - окно сна, по умолчанию 00:00–08:00 местного времени;
  - недельное расписание свободного времени в местном времени (сетка 7×48 по 30 минут);
  - исключения на конкретные даты.
- **ГМ создаёт подбор:** участники (или вся кампания), диапазон дат, длительность, минимум участников (по умолчанию все).
- **Сервер** раскладывает правила каждого в конкретные даты через `java.time.ZoneId` (переход на летнее время учитывается сам), вычитает сон, пересекает расписания и выдаёт лучшие окна. Ранжирование: больше участников, меньше «неудобных» часов (рано утром или поздно вечером у кого-то), раньше по дате.
- **Каждый видит окна в своём местном времени** и подсказку, сколько это у других (например, «у Канады 10:00, у Москвы 18:00»).
- ГМ фиксирует окно. Создаётся объявление и событие, плюс экспорт `.ics`.

## 6. Визуальный язык «Архив Санни»

- **Основа:** контора Санни, то есть бумага, папки-дела, латунь, шестерёнки, штампы, пар. Разделы «Сны» и «Исследования» переходят в ночную тему (`--sunny-night`, лёгкие звёзды или пар).
- **Токены:** `docs/zlatopryady/assets/sunny-tokens.css`. Старые `--parchment`, `--ink`, `--gold`, `--crimson` и всю палитру `--hub-*` заменить.
- **Шрифты.** Важно: в Cinzel и MedievalSharp **нет кириллицы**, сейчас русский текст падает в запасной шрифт. Новый набор (у всех есть кириллица):
  - PT Serif: основной текст;
  - Oswald с разрядкой: подписи, шильдики, кнопки;
  - Roboto Slab 800: только слово SUNNY в логотипе;
  - PT Mono: номера дел, штампы, «машинопись».
- **Маскоты:**
  - кот = гид, подсказки, пустые состояния, загрузка, ошибки;
  - Сундучок = награды, инвентарь, «укус» при ошибке;
  - favicon = эмблема.
  - Сейчас цвета в SVG маскотов зашиты как hex. Перевести их на CSS-переменные из токенов.
- **Анимации** всегда выключаются при `prefers-reduced-motion`.
- **Тон текстов:** канцелярский юмор (см. раздел 7 в `TZ-v1.md`).

## 8. Общие правила для Code на всех этапах

- Работать в ветке `zlatopryady`. Не пушить и не деплоить без явного разрешения Batyr.
- Стек не меняем: Spring Boot (Java 21) + React/Vite + Neon Postgres.
- После каждого этапа должны проходить `./gradlew build` в `backend` и `npm run build` и `npm run lint` в `frontend`.
- Никаких паролей и ключей в коде. Схему БД менять только добавлением. Если нужно переименовать или удалить колонку, сначала описать это в отчёте.
- Отчёт в конце этапа: что сделано, список изменённых и удалённых файлов (`git diff --stat`), что не получилось, вопросы.
